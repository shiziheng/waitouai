# 电视护眼管家（二期）

手机放在电视旁边，孩子**歪头**看电视、凑太近、斜眼看，手机当场出声提醒。

而且会把这些行为记下来，攒够两周能导出一份文字报告，看眼睛的时候给医生看。

---

## 这一版最该看的一句话

先说清楚，免得期待错方向：

> **这个 App 只测「头歪了几度」，测不了「眼睛斜不斜」。**

歪头是个动作，相机看得出来。斜视是个诊断，只有医生能做。

但这两件事确实有关系——孩子老是歪着头看电视，是斜视的常见线索之一，而且歪头看久了本身也可能加重问题。所以它干的是「帮你数清楚孩子一天歪了多少次头、往哪边歪」，不是「告诉你孩子有没有病」。

如果你家孩子已经出现斜眼的迹象，**这份记录拿去给眼科医生，比你的口头描述有用得多**。但检查必须去医院做。

---

## 二期做了什么

一期只做「凑太近」，二期加了「歪头」和「斜眼看」，还加了记录。

| 能力 | 状态 |
|---|---|
| 相机实时预览 | ✅ 前置摄像头，640×480 |
| 人脸 + 478 个关键点 | ✅ MediaPipe Face Landmarker，本地模型 |
| **歪头检测（核心）** | ✅ 两眼连线相对水平的夹角，扣掉手机自己的倾斜 |
| **斜眼看检测（辅助）** | ✅ 虹膜在眼眶里的横向偏移量 |
| 凑太近检测 | ✅ 脸宽倍数 |
| 手机摆放角度自动补偿 | ✅ 校准时同时记住倾斜基线，侧放斜放都不影响判断 |
| 中文语音提醒 | ✅ 歪头时会说「头歪了，往左边正一正」这种具体的话 |
| 提示音 | ✅ 先响一声再说话，更容易抓住注意力 |
| 三路独立判定 | ✅ 各自计时、各自冷却，互不干扰 |
| **按天统计** | ✅ 最近 30 天，歪头次数、总时长、左右倾向 |
| **导出报告给医生** | ✅ 纯文本，一次生成近 14 天汇总 |
| 连电视 / 暂停播放 | ❌ 二期仍然不做 |

### 为什么还是不做电视控制

一期说过的理由仍然成立：依赖电视型号、系统版本、ADB 授权，不确定性太大。

另外加一条现在才想明白的：**孩子歪头看电视的时候，电视暂停反而帮不上忙**。你要的是他坐正，不是让他停下来。出声提醒更直接，也不用折腾半天连不上。

真要连电视，那该是另一个功能——定时关屏、控制观看时长，跟护眼提醒不是一回事。等前面这些做扎实了再谈。

## 装到手机上

**办法一：直接装 APK（推荐，不用连电脑）**

1. 把 `dist/电视护眼管家-1.1.0-debug.apk` 传到手机上。微信「文件传输助手」发给自己最省事。
2. 在手机上点开安装。
3. 提示「未知来源」时，按指引去「设置」里允许微信/文件管理「安装未知应用」，再回来继续。
4. 华为/小米可能再弹「未经应用市场审核」，选「继续安装」或「仍要安装」。

装完桌面出现「电视护眼管家」，点开，允许相机权限。

**办法二：连电脑用 adb**

```bash
adb install -r dist/电视护眼管家-1.1.0-debug.apk
```

**办法三：Android Studio**

打开 `tv-eye-guardian` 目录，等 Sync 完，手机连上，点运行。

> 大小 38 MB，最低 Android 7.0（API 24）。
> debug 签名，自己家里用没问题，上不了应用商店。

## 手机怎么摆（这段最重要）

你说「还没定怎么摆」，这里给个具体建议。

### 推荐：正对孩子的侧脸，跟电视并排

```
        ┌──────────┐
        │   电视    │
        └──────────┘
   ┌─┐                    ┌─────┐
   │沙│                    │ 手机 │  ← 放在电视柜上，跟电视同一面墙
   │发│                    └─────┘
   └─┘        孩子坐在中间
```

要点：

1. **手机和电视在同一面墙附近**，摄像头朝向孩子坐的位置。这样"正在看电视"和"在看手机"能区分开一点。
2. **高度大致和孩子脸齐平**，大概 1 米左右。别俯拍也别仰拍太多。
3. **离孩子 1.5~2.5 米**。太远脸太小，关键点开始飘；太近容易撑满画面。
4. **别放在电视正前方挡视线**，稍微偏一点、偏个 30 度左右反而更好——侧一点能看到孩子脸的侧面，歪头角度更明显。

### 稳一点的话，用什么支架

- **便宜的方案**：手机支架（那种夹在桌子边上的），或者直接用几本书垫在电视柜上。
- **讲究一点的**：小型三脚架 + 手机夹，能调高度和角度。
- **最省事**：手机壳自带的那种"支架模式"，能立住就行。

关键是**别让它动**。校准完以后手机要是被碰歪了，判断会开始飘——所以建议贴个记号，或者干脆用双面胶固定。

### 摆放角度不正怎么办

没关系，这正是二期加的东西。**手机侧放、斜放、甚至转 30 度，都能用**，因为校准时会同时记下"画面本身有多斜"，之后每次判断都减掉这个值，剩下的才是孩子真正多歪的角度。

但有个前提：**校准的时候，孩子的头必须是正的**。这是唯一要注意的。

## 怎么用

### 第一次用

1. **摆好手机**（按上面那段来）。
2. 点「开始监测」，允许相机权限。
3. 让孩子坐到你希望他坐的位置，**摆正头**，正对电视（不是正对手机）停 1~2 秒。
4. 点「校准基准」。屏幕会显示两件事：基准脸宽、基准倾斜。

   如果基准倾斜超过 8°，会提示你「手机本身斜了」——不是错误，只是让你知道一下，后面会自动扣掉。

5. 就好了。让孩子正常看电视就行。

### 平时看什么

主界面上有三块：

- **大状态字**：现在正常 / 正在靠近 / 歪头了 / 看不到孩子
- **倾斜仪表**：一根指针，指到左边或右边。绿色区域是安全范围，指针偏出去就是在歪头，旁边显示具体度数
- **倒计时**：已经异常多久了，还差几秒会提醒

异常超过设定的时间，手机就出声。歪头会说「头歪了，往左边正一正」，靠近会说「太近了，往后退一点」。

### 什么时候要重新校准

换房间、挪了手机、换了孩子坐的位置、把手机碰歪了——**都要重校**。

判断依据是"脸在画面里的大小"和"画面本身的角度"，手机一动，这两个基准就都不准了。

## 设置里能调什么

右上角齿轮，分四块。

### 歪头（重点）

- **阈值**：默认 20°。孩子头偏 20 度以上开始算异常。想更敏感调到 15°，觉得吵就调到 25°。
- **持续多久才提醒**：默认 3 秒。歪一下就回正的不用管。
- **两次提醒间隔**：默认 20 秒。

歪头的判定比靠近更严——因为它比靠近更值得管，这是有意设计的。

### 斜眼看（辅助）

- **阈值**：默认 30°。
- **持续多久**：默认 3 秒。
- **提醒间隔**：默认 30 秒。

这块**精度有限**，当辅助看，别当准。原因见下面「它做不到什么」。

### 距离

- **倍数**：默认 1.20 倍。
- **持续多久**：默认 3 秒。
- **提醒间隔**：默认 15 秒。

### 提醒方式

- **语音提醒**：总开关。
- **提示音**：先响一声再说话。
- **临时调大音量**：播报时把媒体音量抬到 70%，播完还原。手机常年静音的话这个很有用。

## 统计和报告

主界面右上角有个统计图标，点进去能看到：

- **近 14 天汇总**：歪头几次、总共歪了多久、平均每天几次
- **左右倾向**：往左歪多少、往右歪多少。这个对医生有用——**固定往一侧歪，比两边都歪更值得注意**
- **逐日明细**：最近 30 天，每天一行
- **一句话结论**：比如「最近两周歪头明显偏多，建议留意」

底下有个「生成报告」按钮，生成一段纯文本，可以复制或者直接分享（微信发给医生、或者存下来看病时给他看）。

报告里包含：

- 近 14 天汇总数据
- 左右倾向
- 逐日明细
- **观测方式说明**——写清楚这是手机相机估的、不能当诊断，免得医生误会

### 关于数据

- 全部存在手机本地，不上传。
- 统计只记数字（次数、毫秒），**不存任何画面**。
- 最多留 30 天，自动滚动。

## 它做不到什么

老实说清楚。

### 测不了斜视

这一点最关键，重复一遍。

App 里的「斜眼看」是用**虹膜在眼眶里的位置**估的：看两个眼角连成一条线，虹膜中心落在这条线的哪个位置。落在正中间是正视，偏到两边就是偏得厉害。

这个方法的问题：

- **精度有限**。眼睛就那么大，几个像素的误差就能让角度差出十几度。
- **头一转就废**。所以代码里做了限制：头歪超过 25 度就不做眼神判断了，避免把"头转过去看"误判成"斜眼"。
- **它分不清"眼睛偏"和"孩子在瞟一眼旁边"**。真实斜视是持续性的，瞟一眼是瞬间的。靠持续时间能过滤掉一部分，但过滤不干净。

所以：**这块的数是参考，不是结论**。报告里也是这么写的。

### 歪头能测到什么程度

- **能测**：头往左/右倒了几度，持续了多久，一天几次，偏哪边。
- **测不了**：孩子是"脖子歪"还是"眼睛斜了才歪头代偿"。这两种情况外观一样，成因完全不同，只有医生能分辨。
- **前倾/后仰测不了**。相机是 2D 的，头往前探、往后靠，在画面里看不出角度变化。所以孩子探着身子看电视，它认不出来。
- **低头看平板、趴在沙发上，基本失效**。脸的角度一变，关键点位置就变，判断会飘。

### 其他限制

- **孩子贴太近会瞎**。脸撑满画面（超过 85%）时，关键点全部溢出，检测直接丢。这时界面显示「看不到孩子」，不会瞎报——它宁可不判断。
- **不测真实距离**。只知道"比校准的时候大了多少"，不知道是 1.5 米还是 2 米。
- **逆光、暗光、镜头脏了会飘**。表现是频繁「看不到孩子」，而不是乱报。
- **来电、锁屏、切后台，监测自动停**。故意的，不做后台偷用相机的事。
- **两个孩子同时看，只跟最大的那张脸**。画面里有多张脸时，取面积最大的，也就是离得最近的那个。
- **戴眼镜会影响眼神判断**。镜片反光会干扰虹膜定位，歪头判断不受影响。

## 给医生的提示话术

如果你要带孩子去看眼科，可以这么说：

> 「孩子看电视老歪着头，我用手机 App 记了两周，歪头次数明显偏多，而且基本都往左边歪。这是记录，麻烦您看下。」

然后出示报告。

**别这么说**：「App 说孩子有斜视。」——App 没说过这话，也不能说。

## 自己构建

**一条命令打包（推荐）**

```bash
python scripts/release.py
```

它会自动做完这几件事：

1. 补丁版本 +1（`1.1.3` → `1.1.4`），同时 `versionCode` +1
2. 跑单元测试
3. 构建 Debug 包
4. 复制到 `dist/电视护眼管家-<版本>-debug.apk`
5. 清掉 dist 里的旧包

其他用法：

```bash
python scripts/release.py --minor      # 次版本 +1，1.1.3 → 1.2.0
python scripts/release.py --major      # 主版本 +1，1.1.3 → 2.0.0
python scripts/release.py --no-bump    # 不升版本，重新打包
python scripts/release.py --keep-old   # 保留 dist 里的旧安装包
```

**为什么必须升版本**

版本号存在根目录的 `version.properties` 里，App 构建时从那里读。

同一个 `versionCode` 的 APK 覆盖安装，系统有时会认为「没变化」而跳过安装，让人误以为新包没生效。所以每次打包都要把 `versionCode` 至少 +1。**别手改那个文件**，交给脚本。

**手动构建**

```bat
cd tv-eye-guardian
gradlew.bat assembleDebug
gradlew.bat testDebugUnitTest
```

> 需要 JDK 17 和 Android SDK（Platform 34 / Build-Tools 34.0.0）。
> `local.properties` 里的 `sdk.dir` 指向 SDK，换电脑记得改。

产物：`app/build/outputs/apk/debug/app-debug.apk`

22 个单元测试，覆盖：

- 三类异常各自的计时、阈值、冷却
- 冷却期内一直异常时，冷却一过还能再提醒（这个坑真踩过，见下）

### 踩过的坑，记一下

**冷却和统计别混用一个计时器。**

一开始我想"一个 `held` 记两件事"：既表示攒了多久可以提醒了，又表示这轮异常持续了多久用来统计。结果冷却期内每帧都在重置起点，冷却到期的瞬间 `held` 恰好归零，提醒再也不会触发。

后来拆成两个：

- `overSince` — 本轮开始异常的时刻，**冷却期间绝不动它**
- `lastAlertAt` — 上次提醒的时刻，冷却按它算

判断条件也就变成两个独立的条件：

```kotlin
val enoughHeld = now - overSince >= rule.sustainMillis
val cooldownOver = lastAlertAt == NO_TIME || now - lastAlertAt >= rule.cooldownMillis
if (enoughHeld && cooldownOver) { 提醒() }
```

统计另外用 `episodeStart` 记本轮异常什么时候开始，提醒、冷却都不影响它。

**角度归一化别做两次取模。**

`(a % 180 + 180) % 180 - 90` 看着很对称，实际把所有结果平移了 90°——85° 会算出 -5°。单次 `% 180` 再往 ±90 收拢就够了。

## 隐私

- 画面只在手机本地实时处理，**不录像、不截图、不保存、不上传**。
- 统计只存数字，不存画面。
- 没有云端，没有账号。
- 切后台立即停相机。

MediaPipe 会顺带依赖 Google 的 `datatransport`，默认会往 APK 里塞 `INTERNET` 权限。我在清单里把它和 `ACCESS_NETWORK_STATE` 一起显式移除了。

**所以这个 APK 只申请了相机一个权限。** 没有网络权限，系统层面就发不出数据——这比"我们保证不上传"可靠。自己验证：

```bash
aapt dump permissions dist/电视护眼管家-1.1.0-debug.apk
```

## 模型文件

`app/src/main/assets/face_landmarker.task` 是 MediaPipe 官方 Face Landmarker 模型，来源和校验值见 [docs/MODEL_SETUP.md](docs/MODEL_SETUP.md)。

这个模型输出 478 个关键点，比常见的人脸关键点多了一对**虹膜中心**（468、473），「斜眼看」就是靠这两个点估的。

## 下一步能做什么

按价值排：

1. **前倾检测**——孩子探着身子看电视其实比歪头更常见，但 2D 相机测不了，得用面部比例的透视变化去估，误差会大，得先做实验验证。
2. **提醒方式变化**——同一个提醒语反复说，孩子会免疫。改成交替说几句不同的话，或者偶尔换成一声长提示音。
3. **"坐正了"正向反馈**——现在只有提醒，没有表扬。孩子坐正一分钟给个声音反馈，可能比批评有效。
4. **连电视**——定时关屏、控制观看时长，这些是真有用，但要单独做。
