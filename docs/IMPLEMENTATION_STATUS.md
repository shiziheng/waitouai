# 实现状态（二期）

> 最后更新：2026-10-24
> 结论先说：**代码完整、构建通过、22 个单元测试通过；但仍然没在真机上跑过**，交付环境里没有手机。

---

## 一、二期为什么改方向

一期做的是「凑太近就提醒」。二期开工前，用户提了真实诉求：

> 「我核心的功能诉求是检查我们家孩子歪头看电视的毛病，有点斜眼了。」

这句话把优先级整个翻过来了。所以二期的重心不是「再补几个功能」，而是**把「歪头」做成主角**，并且想清楚它和「斜视」的边界在哪。

三个决策是和用户确认过的：

| 问题 | 选择 | 处理 |
|---|---|---|
| 要不要做电视控制 | 先做本地大声提醒 | 电视控制不做，理由见 README |
| 手机怎么摆 | 还没定 | App 里加摆放引导，代码里做角度基线补偿 |
| 要不要统计给医生看 | 要 | 做了按天统计 + 报告导出 |

### 姿态检测的重新定义

原任务书里的「姿态检测」用的是 Pose Landmarker（看身体关节）。但用户的诉求是**头**，不是身体。

所以二期没用 Pose Landmarker，而是继续用 Face Landmarker，从 478 个关键点里算两件事：

- **头倾斜角**：两眼外眼角连线（33 / 263）相对水平线的夹角
- **视线偏离角**：虹膜中心（468 / 473）在「内外眼角连线」上的投影比例

这样不用加载第二个模型，APK 体积不变，精度反而更够——因为脸的细节比身体廓形精细得多。

## 二、这一期砍掉了什么

| 原任务书模块 | 处理 | 原因 |
|---|---|---|
| Pose Landmarker（身体姿态） | 不做 | 诉求是「歪头」，不是「坐姿」 |
| 电视控制（ADB / 局域网） | 不做 | 用户明确选择先做本地提醒；且型号依赖太重 |
| Room 数据库 | 不做 | 按天统计用 SharedPreferences 紧凑文本就够，不值得引入 Room + 迁移 |
| 多页导航 / 首次向导 | 不做 | 单页 + 两个底部面板，家长打开就能用 |
| 前台服务 | 不做 | 只在前台监测，切后台自动停，更安全 |
| 多人脸分别统计 | 不做 | 只跟画面里最大的脸（离得最近的那个） |

## 三、已实现（代码层面）

### 3.1 信号提取（`camera/FaceSignalAnalyzer.kt`）

- CameraX `Preview` + `ImageAnalysis`，640×480，`STRATEGY_KEEP_ONLY_LATEST`，`RGBA_8888`。
- 推理限流约 5 帧/秒，上一帧没出结果直接丢新帧。
- MediaPipe Face Landmarker，`LIVE_STREAM`，**`setNumFaces(2)`**——二期改成取最多两张脸，然后挑面积最大的那张。一期是「取第一张」，两个大人同时入镜时会跟错人。
- 关键点校验：数量 < 478 直接判无效（模型输出异常保护）。
- 脸宽：`abs(454.x - 234.x)`，左右脸颊，抗张嘴眨眼。
- 倾斜角：`atan2(dy, dx)`，用 263（左外眼角）/ 33（右外眼角）。
- 视线角：虹膜中心在眼眶横轴上的投影比例 `t`，`abs((t - 0.5) * 180)`。
  **约束：头倾斜 > 25° 时直接返回 null，不做眼神判断**——否则会把「头转过去看」误判成斜眼。
- 脸宽 > 85% 画面 → 回调 `onFaceTooLarge()`，上层显示「看不到孩子」而不是「太近」。
- EMA 平滑：脸宽/倾斜 α=0.35，视线 α=0.25。

### 3.2 角度处理（`domain/FaceSignal.kt`）

```kotlin
fun normalizeTilt(angle: Float): Float  // 折回 (-90, 90]
fun residualTilt(rawTilt: Float, baselineTilt: Float) = normalizeTilt(rawTilt - baselineTilt)
```

`residualTilt` 是关键：**手机侧放斜放不影响判断**。校准记下画面基线，之后每次减掉。

### 3.3 判定（`domain/MonitorEngine.kt`）

三类异常共用一套 `SustainedAnomalyDetector`，但各自独立实例、独立计时、独立冷却：

| 异常 | 默认阈值 | 持续 | 冷却 |
|---|---|---|---|
| `HEAD_TILT` 歪头 | 15° | 2 s | 20 s |
| `LOOK_ASIDE` 斜眼看 | 30° | 3 s | 30 s |
| `TOO_CLOSE` 太近 | 1.20× | 3 s | 15 s |

歪头判定比靠近更严（2 秒 vs 3 秒，20 秒 vs 15 秒冷却），因为它是重点。

丢帧容忍 1200 ms：孩子低头捡个东西不清零。

`FrameResult.finishedDurations` 返回刚刚结束的异常持续时长，**短于 1 秒的不记账**，避免统计被抖动灌满。

### 3.4 数据（`data/`）

**`SettingsStore`**
- 校准：`baselineFaceWidth` + `baselineTilt`
- 三类规则各 4 个参数（enabled / threshold / sustain / cooldown）
- 提醒方式：`voiceEnabled` / `boostVolume` / `alertSound`

**`StatsStore`**
- `DayStats(date, closeCount, closeMillis, tiltCount, tiltMillis, tiltLeftCount, tiltRightCount, lookCount, lookMillis, alertCount, watchMillis)`
- 存法：一天一行紧凑文本 `date|c|cm|t|tm|tl|tr|l|lm|a|w`，最多 30 天，自动滚动
- `buildReport()` 生成给医生的纯文本：近 14 天汇总 + 左右倾向 + 逐日明细 + 观测方式说明

### 3.5 语音（`audio/ReminderSpeaker.kt`）

- 系统 `TextToSpeech`，简体中文，语速 0.95。
- **歪头提醒带方向**：「头歪了，往左边正一正」/「头歪了，往右边正一正」——比笼统的「坐好」有用。
- 先响一声 `ToneGenerator` 提示音再说话（可关），更容易抓注意力。
- 播报前媒体音量临时抬到 70%（可关），播完或 6 秒兜底恢复。
- 缺中文语音包 / 引擎初始化失败 → 界面弹提示，不静默失效。

### 3.6 界面（`ui/`）

**主界面**（可滚动单页）
- 顶部：统计入口 + 设置入口
- 相机卡片
- 大字状态：正常 / 正在靠近 / 歪头了 / 看不到孩子 / 未校准
- 指标卡：**倾斜仪表**（Canvas 弧线 + 指针 + 安全区着色）、距离条、视线条
- 开始/停止、校准按钮
- **免责声明**（常驻，不是折叠的）：「这个 App 只记录「歪头」这个动作，不能判断是否斜视。如果孩子歪头看电视已经持续一段时间，建议去眼科做一次检查」

**设置面板**：歪头（重点）→ 斜眼看（辅助）→ 距离（次要）→ 提醒方式 → 校准

**统计面板**：14 天汇总卡、左右倾向条、逐日明细、生成报告 + 分享/复制

### 3.7 界面状态

```kotlin
enum class LiveStatus { IDLE, NOT_CALIBRATED, NO_FACE, SAFE, WARNING, ALERTING, ERROR }
```

- 人脸超时 1500 ms → 打回 `NO_FACE`，不误判成「正常」
- 监测时长按 10 秒一段累加，切后台不丢当前段
- 校准取倾斜角的**中位数**（不是均值）——避免孩子正好在歪头那一刻校准，把基线带偏
- 基线 > 8° 时提示「手机本身斜了」，只是提示，不阻拦校准

## 四、开发过程中修掉的两个真 bug

记下来，因为都是「看起来对、实际错」的那种。

### bug 1：冷却和统计混用一个计时器，导致提醒永久失效

最初设计想用一个 `held` 同时表示「攒够时间了吗」和「这轮异常多久了」。结果：

1. 冷却期内每帧都把起点推到 `now`；
2. 冷却到期的那一帧，`held` 恰好 = 0；
3. `held < sustain` 成立 → 不提醒；
4. 下一帧起点又被推 → 永远 `< sustain`。

**孩子一直歪头，App 只响一次，之后再也不响。**这恰恰是最该反复提醒的场景。

修法：拆成三个独立字段。

```kotlin
private var overSince = NO_TIME    // 本轮开始异常；冷却期间绝不动
private var lastAlertAt = NO_TIME  // 上次提醒，冷却按它算
private var epochStart = NO_TIME   // 统计用，提醒/冷却都不影响
```

判断也拆成两个独立条件：

```kotlin
val enoughHeld = now - overSince >= rule.sustainMillis
val cooldownOver = lastAlertAt == NO_TIME || now - lastAlertAt >= rule.cooldownMillis
if (enoughHeld && cooldownOver) 提醒()
```

回归测试：`冷却期内一直歪头，冷却一过还会再提醒`。

### bug 2：角度归一化做了两次取模，整体平移 90°

```kotlin
// 错：看着对称，实际所有结果 -90°
var a = (angle % 180f + 180f) % 180f - 90f
```

`85°` 会算成 `-5°`，`0°` 会算成 `-90°`。测试一跑就暴露了。

```kotlin
// 对：单次取模，再往 ±90 收拢
var a = angle % 180f
if (a > 90f) a -= 180f
if (a <= -90f) a += 180f
```

### 顺带修正的测试期望

有三条测试的期望值本身写错了（不是实现错），已按真实语义改正并在注释里写明理由：

- 「跨 180° 边界」：`residualTilt(-88, 88)` 净差 `-176°`，折回是 `+4°` 而不是 `-4°`。物理上也讲不通——手机基线不可能到 88°。改成验算 `(-60, 70) → +50` 和 `(-89.9, 89.9) → +0.2`。
- 「异常结束后统计持续时长」：起 0、止 6000，就是 6000，中间那次提醒不该影响统计。
- 「恢复正常后计时清零」：`3400 - 2000 = 1400` 已攒时长，`2000 - 1400 = 600` 才是剩余。

## 五、未验证 / 已知限制

**必须说清楚，下面这些都还没在真机上验证过：**

| 项目 | 状态 |
|---|---|
| 真机相机预览与关键点稳定性 | ❌ 未验证（无 Android 设备） |
| 15° 歪头阈值是否符合真实场景 | ❌ 未验证，需要现场调 |
| 虹膜定位在真实光照下的精度 | ❌ 未验证，这一项最没底 |
| 中文 TTS 在具体机型上的发音 | ⚠️ 代码完成，未听感验证 |
| 音量增强在 MIUI 上的行为 | ⚠️ 代码完成，MIUI 有额外音量管控 |
| 长时间运行发热/耗电 | ❌ 未测 |
| 眼镜反光对虹膜定位的影响 | ❌ 未测，预计会有影响 |
| 统计文本格式解析的边界 | ⚠️ 有单测覆盖解析，但没跑过 30 天真实数据 |

已知设计限制：

1. **测不了斜视。** 虹膜投影法只能估「眼睛往哪边偏了多少」，精度有限，且分不清「持续偏」和「瞟一眼」。报告里明确写了不构成诊断。
2. **2D 相机测不了前倾。** 头往前探、往后仰，画面里角度不变，认不出来。
3. **不测真实距离。** 只有「相对校准位置大了多少」的倍数。
4. **贴太近会失效。** 脸 > 85% 画面时报「看不到孩子」，不报「太近」——宁可说不知道。
5. **歪头 > 25° 时不做眼神判断。** 避免把头转误判成斜眼，代价是大幅歪头时看不到视线数据。
6. **手机移动后必须重校。** 脸宽和倾斜两个基准都是绝对量。
7. **只跟画面里最大的脸。** 二孩家庭同时看电视时，只会盯住离得最近的那个。
8. **前置摄像头固定**，没做切换。

## 七、下一步

按性价比排：

1. **真机跑一周，调阈值。** 15° / 2 秒 / 20 秒都是拍脑袋值。先拿真手机在孩子常坐的位置测，重点看误报率——误报多的 App 家长三天就卸载。
2. **验证虹膜精度。** 这块最没底。建议做法：让孩子分别正看、往左瞟、往右瞟，各拍一段，人工标注后跟 App 读数比对，算出误差分布。如果误差太大，就把它降级成「仅供参考」或者干脆去掉。
3. **前倾检测。** 用面部比例的透视变化去估。误差会大，但「探着身子看电视」可能比歪头更常见。
4. **双阈值迟滞。** 单阈值在边界上会抖，改成「进入 15° / 退出 10°」会稳很多。
5. **提醒语轮换。** 同一句话反复说孩子会免疫，交替几句不同的更有效。
6. **正向反馈。** 现在只有批评没有表扬。坐正一分钟给个声音反馈，可能比喊话有用。
7. 电视控制放最后。
